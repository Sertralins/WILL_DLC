# `data/levels/0001.json` 字段说明

> 依据：`scripts/core/level_data.gd`（数据模型）、`scripts/core/condition_engine.gd`（条件表达式引擎）、`autoload/rule_engine.gd`（判定引擎）、`docs/文件结构与开发路线.md` §5（Schema）。

## 文件全貌

```json
{
  "level_id": "0001",
  "title": "黑伞",
  "row_count": 2,
  "unlock": "",

  "rows": [
    {
      "id": "L", "character": "A", "position": "0,3", "previous": "start",
      "blocks":  [ { "id": "PanelA1", "text_key": "0001_PanelA1" },
                   { "id": "PanelA2", "text_key": "0001_PanelA2" } ],
      "strips":  [ { "id": "A1", "text_key": "0001_A1" },
                   { "id": "A2", "text_key": "0001_A2" } ],
      "variants": []
    },
    {
      "id": "R", "character": "B", "position": "0,6", "previous": "start",
      "blocks":  [ { "id": "PanelB1", "text_key": "0001_PanelB1" },
                   { "id": "PanelB2", "text_key": "0001_PanelB2" } ],
      "strips":  [ { "id": "B1", "text_key": "0001_B1" } ],
      "variants": [ { "id": "PanelB2_1", "base": "PanelB2", "text_key": "0001_PanelB2_1" } ]
    }
  ],

  "endings": {
    "S1":   { "rank": "S",   "rep": 325, "change": [ { "type": "REPLACE", "data": "PanelB2_1" } ] },
    "BAD1": { "rank": "Bad", "rep": 0,   "change": [] }
  },

  "conditions": [
    { "expr": "SS(A2,A1)", "ending": "S1" },
    { "expr": "", "ending": "BAD1", "fallback": true }
  ]
}
```

## 一、顶层字段

| 字段 | 本关取值 | 含义 | 原版对应 |
|---|---|---|---|
| `level_id` | `"0001"` | 关卡 4 位字符串编号；同时是文件名与剧情文本表名（`0001.txt`） | `LEVELID` |
| `title` | `"黑伞"` | 关卡名，信件墙（map 场景）上显示 | — |
| `row_count` | `2` | 行数。可由 `rows` 推导，属冗余字段，保留便于快速判断 | `ROWCOUNT` |
| `unlock` | `""` | 解锁条件表达式。**空 = 初始即解锁**；非空时用 `ConditionEngine` 求值（与 `conditions` 共用同一语法），未解锁关卡在信件墙上置灰 | `UNLOCK` |

## 二、`rows[]` — 信件行

每封信由若干"行"组成：`L`（左行）/ `R`（右行）/ `M`（中缝，三行关卡用）。

| 字段 | L 行 | R 行 | 含义 | 原版对应 |
|---|---|---|---|---|
| `id` | `"L"` | `"R"` | 行标识，也是字段族前缀 | 字段族前缀 |
| `character` | `"A"` | `"B"` | 本行默认角色，引用 `data/characters.json` 的 id（A：紫红 `#905f80`；B：蓝灰 `#505070`） | `LNAMECODE` |
| `position` | `"0,3"` | `"0,6"` | 信件墙布局坐标 `"列,行"`，map 场景摆放信件用 | `LPOSITION` |
| `previous` | `"start"` | `"start"` | 通信线接续：`"start"` = 这是第一封信；否则写 `"关卡:行"`（如 `"0002:L"`）表示本行是那行的下一封 | `LPREVIOUS` |

### 每行的三类句子

| 字段 | 类型 | 含义 | 原版对应 |
|---|---|---|---|
| `blocks[]` | 固定句（黑块，TYPE 0） | 不可拖拽的首尾框架。约定：`blocks[0]` = 顶部框架（开头），最后一项 = 底部弹性块（结尾） | `TYPE 0` |
| `strips[]` | 可排序句（字条，TYPE 1） | 玩家可拖拽重排的句子 —— 本关玩法核心 | `TYPE 1` |
| `variants[]` | 条件句（TYPE 2） | **不进初始界面**；结局 `REPLACE` 时才替换 `base` 句登场 | `TYPE 2` |

### 句子条目的公共字段

| 字段 | 含义 |
|---|---|
| `id` | 句子唯一标识，条件表达式与结局 `change` 均引用它 |
| `text_key` | 剧情文本表键：去同目录同名 `0001.txt`（PO-lite 格式，`msgctxt "STRINGS.DIALOG.CONTENT.<text_key>"`）查正文 |
| `text`（可选） | 内联正文，优先级高于 `text_key`；两者都缺时原样显示 `text_key` 以便排查漏配 |
| `base`（仅 variants） | 该条件句替换的目标句 id |

本关具体分布：

| 行 | 固定句 | 字条 | 条件句 |
|---|---|---|---|
| L（角色 A） | `PanelA1`（顶框）、`PanelA2`（底块） | `A1`、`A2` | — |
| R（角色 B） | `PanelB1`（顶框）、`PanelB2`（底块） | `B1` | `PanelB2_1`（base = `PanelB2`） |

## 三、`endings` — 结局表

结构：`{ 结局id: { rank, rep, change[] } }`。

| 字段 | 含义 |
|---|---|
| `rank` | 结局评级，取值 `S / A / B / C / D / E / Bad / Z` |
| `rep` | 声望值，按 **325 / 131 / 52 / 21 / 8 / 3 / 0 对数递减**；结算时累加进 `GameState.total_rep` |
| `change[]` | 结局达成后对信件的改写指令序列，可组合多条 |

`change[]` 指令类型：

| `type` | `data` | 效果 |
|---|---|---|
| `REPLACE` | 条件句（variant）id | 将该句的 `base` 句替换为该条件句（信件文本因此改变） |
| `DRA` / `D` | 句子 id | 删除该句 |

本关两个结局：

| 结局 | `rank` | `rep` | `change` | 含义 |
|---|---|---|---|---|
| `S1` | `S` | 325 | `REPLACE PanelB2_1` | 好结局：+325 声望，R 行结尾 `PanelB2` 被替换为 `PanelB2_1` |
| `BAD1` | `Bad` | 0 | 无 | 坏结局：0 声望，信件保持原样 |

## 四、`conditions` — 判定表

**按数组顺序逐条求值，第一个命中的条目决定结局。**

| 字段 | 含义 |
|---|---|
| `expr` | 条件表达式（`ConditionEngine` 求值）；**空表达式恒为真** |
| `ending` | 命中后结算的结局，必须是 `endings` 的键 |
| `fallback` | `true` 标记兜底条目（配合空 `expr` 使用） |

本关两条判定：

| 条目 | `expr` | 命中结果 |
|---|---|---|
| 1 | `SS(A2,A1)` | 合并序列（各行句子按行序拼接的完整顺序）中 **A2 严格排在 A1 之前** → 结算 `S1` |
| 2 | `""` + `fallback: true` | 兜底恒真 → 结算 `BAD1` |

### 可用的条件函数（本关只用了 `SS`）

| 函数 | 语义 |
|---|---|
| `SS(A,B[,C])` | 严格顺序链：A 在 B（在 C）之前 |
| `OS(A,B)` | A 紧邻 B 之前 |
| `OSS(A,B)` / `S(A,B)` | A、B 相邻（不分前后） |
| `IN(L/R/M,X)` | X 当前位于左行 / 右行 / 中缝 |
| `CURRENT / ELLE / SRANK / STORY / READ / ACHIEVE` | 跨关世界状态查询（历史结局、已获 S 评级、已收集等） |

布尔运算：`&&`、`||`、`!`、`()` 分组；裸标识符 = 查询条件句触发状态。

## 五、串起来看这一关的玩法

1. 玩家读两封信 —— L 行（角色 A）与 R 行（角色 B）；初始阅读顺序 = 首固定块 → 字条 → 其余固定块。
2. 玩家拖拽重排字条（主要是 L 行的 `A1` / `A2`）。
3. 提交后 `RuleEngine.judge()` 按序求值 `conditions`：
   - `SS(A2,A1)` 为真（A2 排在 A1 前）→ **S1**：+325 声望，R 行结尾 `PanelB2` 被替换为 `PanelB2_1`，重读/演绎时呈现新文本；
   - 否则落入兜底 → **BAD1**：0 声望，信件无变化。
