# 人物剪影：序列帧与 Spine

## 当前检查（2026-09-17）

伊芙使用 AnimatedSprite2D：240 帧，24 FPS，10 秒循环，每帧 512×1024。
PNG 文件共约 19.78 MiB。全部解码为 RGBA8 时，像素数据理论占用 480 MiB；当前导入设置为无损压缩、无 mipmap。这不是实际 GPU 测量值。同一份 SpriteFrames 的多个实例可共享纹理，不能直接按人数乘算。

## 已调整的固定动画框

`CharacterAnim.setup_path` 继续接收动画场景。场景根节点为 Control，它的 size 表示设计画布，例如 512×1024；内部可以放 AnimatedSprite2D，以后也可以放 SpineSprite。

新组件 `character_frame_fit.gd` 根据外层 AnimSlot 的大小等比适配设计画布，横向居中、底部对齐。槽位 position 决定人物位置；槽位 scale 和人物滑入仍由场景管理。原来同为 512×1024 的画布保持原效果。每帧不重新计算人物可见轮廓，避免位置抖动。不强制裁切原有画布外的美术内容。

## 是否换 Spine

固定位置并不依赖 Spine；更换格式主要解决动画素材的组织、纹理用量和后续动作编辑。

- 继续序列帧：最容易保持原版动作，制作工作少，但整段纹理开销较高。
- 真正的 Spine 骨骼动画：复用身体、衣服、头发等部件，由骨骼和网格变形驱动；通常有机会减少纹理用量，但具体效果需实测，运行时也有骨骼计算开销。
- 把 240 帧装进 Spine 的序列附件：本质仍是 240 帧，不能获得骨骼方案的主要节省。

补查发现原作骨骼数据以 `.skel.txt`、`.atlas.txt` 保存在 `text/spines.bundle`，其中骨骼文件实际为旧版二进制；它们属于原作角色，没有仇有余。此前按标准扩展名搜索遗漏了这些文件。若只有逐帧成图，需要重新拆分美术、补遮挡部分、绑定骨骼并制作动画，不能无损自动反推出原骨骼。

建议现阶段保留序列帧完成玩法，用统一动画框固定位置。若后续角色很多或实测内存成为瓶颈，先用一个角色做 Spine 对照样片，再决定是否批量重做。此轮没有安装 Spine 运行库，也没有将 PNG 冒充骨骼资源。

官方 Godot 接入与资源格式说明：https://esotericsoftware.com/spine-godot
官方骨骼/图像工作流：https://esotericsoftware.com/spine-images
接入前需确认 Spine 编辑器授权及运行库与引擎版本匹配。
